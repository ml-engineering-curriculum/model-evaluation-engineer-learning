# Resources for mod-108-agent-and-tool-eval (Agent and Tool-Use Evaluation: Trajectories, Sandboxes, and Partial Credit)

Primary sources for the material in this module. Every citation is a paper, a first-party repository, or official documentation from the benchmark or harness maintainers. No secondary summaries.

## Why single-turn scoring breaks for agents (Chapter 1)

- **Yao, S., Zhao, J., Yu, D., Du, N., Shafran, I., Narasimhan, K., & Cao, Y. (2023).** "ReAct: Synergizing Reasoning and Acting in Language Models." *ICLR*. [arXiv:2210.03629](https://arxiv.org/abs/2210.03629). The reference for the interleaved reason-and-act loop that most modern agent harnesses (`basic_agent`, SWE-agent, OpenHands) implement in some form. Chapter 1 uses ReAct as the canonical shape for "the model observes tool output before its next message."
- **Schick, T., Dwivedi-Yu, J., Dessì, R., Raileanu, R., Lomeli, M., Zettlemoyer, L., Cancedda, N., & Scialom, T. (2023).** "Toolformer: Language Models Can Teach Themselves to Use Tools." *NeurIPS*. [arXiv:2302.04761](https://arxiv.org/abs/2302.04761). Background on tool-augmented language models; frames why "output object grows from string to trajectory" is a training-side as well as evaluation-side shift.
- **Chen, M., Tworek, J., Jun, H., et al. (2021).** "Evaluating Large Language Models Trained on Code." [arXiv:2107.03374](https://arxiv.org/abs/2107.03374). The Codex paper. Chapter 1 cites the mod-107 sandbox lineage here — the code-execution eval as the immediate precursor to agent-eval sandboxing.
- **OpenAI Assistants and Responses API.** [platform.openai.com/docs/assistants](https://platform.openai.com/docs/assistants/overview) and [platform.openai.com/docs/api-reference/responses](https://platform.openai.com/docs/api-reference/responses). Reference for the vendor-supplied agent loops named alongside ReAct as instances of the "harness owns the loop" pattern. <!-- needs-research: Assistants API stability and successor status; the Responses API surface has evolved through 2025 and specific endpoint URLs may drift. -->
- **Anthropic — tool use documentation.** [docs.anthropic.com/en/docs/tool-use](https://docs.anthropic.com/en/docs/agents-and-tools/tool-use/overview). Reference for the Anthropic tool-use loop; another example of the vendor-supplied agent-harness shape.

## Trajectory scoring and budget tracking (Chapter 2)

- **Chen, M., Tworek, J., Jun, H., et al. (2021).** "Evaluating Large Language Models Trained on Code." [arXiv:2107.03374](https://arxiv.org/abs/2107.03374). The original `pass@k` unbiased estimator (§2). The `pass^k` variant discussed in Chapter 2 (all `k` runs must pass) is a consistency metric derived from the same multi-sample setup.
- **UK AISI Inspect — Eval Logs.** [inspect.aisi.org.uk/eval-logs.html](https://inspect.aisi.org.uk/eval-logs.html). Reference for the `.eval` log format Chapter 2 assumes as a canonical trajectory serialization. Explicitly documents the per-sample message list, tool-call records, usage/latency fields, and `Score.metadata` channel used to carry the trajectory-signal vector.
- **UK AISI Inspect — Scorers.** [inspect.aisi.org.uk/scorers.html](https://inspect.aisi.org.uk/scorers.html). Reference for the `@scorer` / `@metric` decorators, `Score.value` / `Score.metadata` split, and per-sample-vs-per-metric aggregation semantics.
- **Efron, B., & Tibshirani, R. J. (1993).** *An Introduction to the Bootstrap.* Chapman & Hall. The bootstrap reference cited when Chapter 2 argues "bootstrap over trajectories, not per-step calls." <!-- needs-research: preferred citation form for the Efron & Tibshirani text; some tracks in this org cite Efron 1979 (Annals of Statistics) as the origin instead. -->
- **Bowman, S. R., & Dahl, G. E. (2021).** "What Will it Take to Fix Benchmarking in Natural Language Understanding?" *NAACL*. [arXiv:2104.02145](https://arxiv.org/abs/2104.02145). Background for the "never report accuracy without a budget" and "budget is part of the task" positions.

## SWE-bench reproduction end-to-end (Chapter 3)

- **Jimenez, C. E., Yang, J., Wettig, A., Yao, S., Pei, K., Press, O., & Narasimhan, K. (2024).** "SWE-bench: Can Language Models Resolve Real-World GitHub Issues?" *ICLR*. [arXiv:2310.06770](https://arxiv.org/abs/2310.06770). The SWE-bench paper. Defines the twelve-repository dataset, the FAIL_TO_PASS / PASS_TO_PASS grading model, and the per-instance Docker container harness.
- **SWE-bench site and reference harness.** [swebench.com](https://www.swebench.com/) and [github.com/princeton-nlp/SWE-bench](https://github.com/princeton-nlp/SWE-bench). Reference `swebench` Python package, `swebench.harness.docker_build`, `swebench.harness.run_evaluation`, and the leaderboard. Also the source of the current `princeton-nlp/SWE-bench_Verified` and `princeton-nlp/SWE-bench_Lite` Hugging Face dataset revisions.
- **OpenAI / Princeton (2024).** "Introducing SWE-bench Verified." OpenAI blog post announcing the 500-instance human-verified subset. [openai.com/index/introducing-swe-bench-verified](https://openai.com/index/introducing-swe-bench-verified/). Documents the manual review protocol and the specific categories of full-split defect (ambiguous spec, brittle tests, unreasonable required fix) that Verified filters out.
- **Yang, J., Jimenez, C. E., Wettig, A., Lieret, K., Yao, S., Narasimhan, K., & Press, O. (2024).** "SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering." *NeurIPS*. [arXiv:2405.15793](https://arxiv.org/abs/2405.15793). The SWE-agent paper. Reference for the ACI (agent-computer interface) framing and the specific tool set (`edit`, `open`, `scroll`, `find_file`, `search_file`) that Chapter 3 uses as the canonical "agent-style loop" example.
- **SWE-agent repository.** [github.com/SWE-agent/SWE-agent](https://github.com/SWE-agent/SWE-agent). Reference implementation and configuration files; the source of the specific published SWE-bench numbers most reproductions target.
- **Wang, X., Li, B., Song, Y., Xu, F. F., Tang, X., Zhuge, M., Pan, J., Song, Y., Li, B., Singh, J., Tran, H. H., Li, F., Ma, R., Zheng, M., Qian, B., Shao, Y., Muennighoff, N., Zhang, Y., Hui, B., Lin, J., Brennan, R., Peng, H., Ji, H., & Neubig, G. (2024).** "OpenHands: An Open Platform for AI Software Developers as Generalist Agents." [arXiv:2407.16741](https://arxiv.org/abs/2407.16741). The OpenHands (formerly OpenDevin) paper. Reference for the second most-widely-benchmarked SWE-bench harness.
- **OpenHands repository.** [github.com/All-Hands-AI/OpenHands](https://github.com/All-Hands-AI/OpenHands). Reference implementation.
- **Aider — repository and documentation.** [aider.chat](https://aider.chat/) and [github.com/paul-gauthier/aider](https://github.com/paul-gauthier/aider). Reference for the simpler edit-loop harness that Chapter 3 names as a third mainstream option; the SWE-bench leaderboard has Aider-based entries.
- **Hugging Face `datasets.load_dataset`.** [huggingface.co/docs/datasets/en/package_reference/loading_methods#datasets.load_dataset](https://huggingface.co/docs/datasets/en/package_reference/loading_methods#datasets.load_dataset). Reference for the `revision=` argument Chapter 3 calls out as mandatory for pinning the SWE-bench dataset SHA against silent re-releases.
- **`git apply` / unified-diff format.** [git-scm.com/docs/git-apply](https://git-scm.com/docs/git-apply). Reference for the `--recount --whitespace=fix` lenient-apply mode named in the "patch parses but modifies the wrong file" pitfall.

## Interactive sandboxes: WebArena, GAIA, AgentBench (Chapter 4)

- **Zhou, S., Xu, F. F., Zhu, H., Zhou, X., Lo, R., Sridhar, A., Cheng, X., Ou, T., Bisk, Y., Fried, D., Alon, U., & Neubig, G. (2024).** "WebArena: A Realistic Web Environment for Building Autonomous Agents." *ICLR*. [arXiv:2307.13854](https://arxiv.org/abs/2307.13854). The WebArena paper. Defines the five containerized web applications (OneStopShop / Reddit / GitLab / a CMS / OpenStreetMap), the browser-state-plus-database evaluators, and the reference reset protocol.
- **WebArena site and reference stack.** [webarena.dev](https://webarena.dev/) and [github.com/web-arena-x/webarena](https://github.com/web-arena-x/webarena). Reference Docker Compose bundle, `browser_env`, per-task evaluator library, and reset script.
- **Koh, J. Y., Lo, R., Jang, L., Duvvur, V., Lim, M. C., Huang, P.-Y., Neubig, G., Zhou, S., Salakhutdinov, R., & Fried, D. (2024).** "VisualWebArena: Evaluating Multimodal Agents on Realistic Visual Web Tasks." *ACL*. [arXiv:2401.13649](https://arxiv.org/abs/2401.13649). The VisualWebArena extension; adds screenshots and visual-grounding tasks to WebArena's shape.
- **Mialon, G., Fourrier, C., Swift, C., Wolf, T., LeCun, Y., & Scialom, T. (2024).** "GAIA: a benchmark for General AI Assistants." *ICLR*. [arXiv:2311.12983](https://arxiv.org/abs/2311.12983). The GAIA paper. Defines the three-level (1 / 2 / 3) open-web research tasks, the exact-match with normalizer grader, and the hidden-test-set evaluation-server workflow.
- **GAIA leaderboard.** [huggingface.co/spaces/gaia-benchmark/leaderboard](https://huggingface.co/spaces/gaia-benchmark/leaderboard). Reference for the current submission format and validation split.
- **Liu, X., Yu, H., Zhang, H., Xu, Y., Lei, X., Lai, H., Gu, Y., Ding, H., Men, K., Yang, K., Zhang, S., Deng, X., Zeng, A., Du, Z., Zhang, C., Shen, S., Zhang, T., Su, Y., Sun, H., Huang, M., Dong, Y., & Tang, J. (2024).** "AgentBench: Evaluating LLMs as Agents." *ICLR*. [arXiv:2308.03688](https://arxiv.org/abs/2308.03688). The AgentBench paper. Reference for the eight-environment portfolio (OS shell, database, KG, card game, house-holding, web shopping, web browsing, lateral-thinking puzzles) and the per-environment success criteria.
- **AgentBench repository.** [github.com/THUDM/AgentBench](https://github.com/THUDM/AgentBench). Reference implementation.
- **BrowserGym.** [github.com/ServiceNow/BrowserGym](https://github.com/ServiceNow/BrowserGym). A Playwright-backed browser-agent framework that ships as one of the mainstream ways to run against WebArena / VisualWebArena / MiniWoB from a common tool surface; referenced in exercise-03 as an agent-implementation option.
- **International Internet Preservation Consortium — WARC file specification.** [iipc.github.io/warc-specifications](https://iipc.github.io/warc-specifications/). Reference for the Web ARChive record format used in Strategy 2 (record-and-replay).
- **mitmproxy documentation.** [docs.mitmproxy.org](https://docs.mitmproxy.org/stable/). Reference for the HTTP-record-and-replay proxy Chapter 4 names as the canonical Strategy-2 tool.
- **Playwright — network interception.** [playwright.dev/docs/network](https://playwright.dev/docs/network). Reference for the browser-side network intercept API cited alongside mitmproxy as a Strategy-2 implementation option.
- **Internet Archive Wayback Machine.** [web.archive.org](https://web.archive.org/). Reference for the frozen-source URL rewriting pattern in Strategy 3.
- **Shi, T., Karpathy, A., Fan, L., Hernandez, J., & Liang, P. (2017).** "World of Bits: An Open-Domain Platform for Web-Based Agents" (MiniWoB). *ICML*. [proceedings.mlr.press/v70/shi17a.html](https://proceedings.mlr.press/v70/shi17a.html). Background on the earlier miniature-web-tasks benchmark that WebArena's design responds to.
- **Deng, X., Gu, Y., Zheng, B., Chen, S., Stevens, S., Wang, B., Sun, H., & Su, Y. (2023).** "Mind2Web: Towards a Generalist Agent for the Web." *NeurIPS*. [arXiv:2306.06070](https://arxiv.org/abs/2306.06070). An alternative web-agent benchmark; useful for the "your product's web surface is not WebArena's" scoping argument.
- **Xu, F. F., Song, Y., Li, B., Tang, Y., Jain, K., Bao, M., Wang, Z. Z., Zhou, X., Guo, Z., Cao, M., Yang, M., Lu, H. Y., Martin, A., Su, Z., Maben, L., Mehta, R., Chi, W., Jang, L., Xie, Y., Zhou, S., & Neubig, G. (2024).** "TheAgentCompany: Benchmarking LLM Agents on Consequential Real World Tasks." [arXiv:2412.14161](https://arxiv.org/abs/2412.14161). A more recent multi-service enterprise-workflow benchmark that inherits WebArena's contain-the-environment strategy; useful comparison point for Chapter 4's determinism-strategy taxonomy.

## Partial-credit rubrics for trajectories (Chapter 5)

- **Zheng, L., Chiang, W.-L., Sheng, Y., Zhuang, S., Wu, Z., Zhuang, Y., Lin, Z., Li, Z., Li, D., Xing, E. P., Zhang, H., Gonzalez, J. E., & Stoica, I. (2023).** "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena." *NeurIPS Datasets & Benchmarks*. [arXiv:2306.05685](https://arxiv.org/abs/2306.05685). The foundational LLM-as-judge paper. Every bias-control the chapter cites (position, verbosity, self-enhancement) traces to a finding here. Chapter 5 assumes the reader has already worked through this paper via mod-105.
- **Panickssery, A., Bowman, S. R., & Feng, S. (2024).** "LLM Evaluators Recognize and Favor Their Own Generations." [arXiv:2404.13076](https://arxiv.org/abs/2404.13076). The self-preference finding. Reference for the Chapter 5 rule "use a judge model distinct from the agent model."
- **Wang, P., Li, L., Chen, L., Cai, Z., Zhu, D., Lin, B., Cao, Y., Kong, L., Liu, Q., Liu, T., & Sui, Z. (2023).** "Large Language Models are not Fair Evaluators." [arXiv:2305.17926](https://arxiv.org/abs/2305.17926). Position-bias documentation and calibrated pairwise aggregation. Complementary to Zheng et al.
- **Cohen, J. (1960).** "A Coefficient of Agreement for Nominal Scales." *Educational and Psychological Measurement*, 20(1), 37–46. Cohen's κ; the reference for the judge-vs-human calibration protocol in exercise-04.
- **Cohen, J. (1968).** "Weighted kappa: Nominal scale agreement provision for scaled disagreement or partial credit." *Psychological Bulletin*, 70(4), 213–220. Weighted κ; the reference for scoring ordinal 0–4 anchor rubrics where anchor-adjacent disagreements should not count as full disagreement.
- **Landis, J. R., & Koch, G. G. (1977).** "The Measurement of Observer Agreement for Categorical Data." *Biometrics*, 33(1), 159–174. The κ-interpretation thresholds (`< 0.4` poor, `0.4–0.6` fair, `0.6–0.8` substantial, `> 0.8` almost perfect) used as the `use / re-anchor / do-not-use` acceptance criterion.
- **Krippendorff, K. (2011).** "Computing Krippendorff's Alpha-Reliability." University of Pennsylvania departmental paper. [repository.upenn.edu/asc_papers/43](https://repository.upenn.edu/asc_papers/43/). Reference for the multi-rater inter-annotator agreement statistic used when the exercise-04 gold set has three or more raters.
- **Zheng, T., Zhang, G., Shen, T., Liu, X., Lin, B. Y., Fu, J., Chen, W., & Yue, X. (2024).** "OpenCodeInterpreter: Integrating Code Generation with Execution and Refinement." [arXiv:2402.14658](https://arxiv.org/abs/2402.14658). Background reference for the "critique-and-refine" pattern that motivates the free-form-critique rubric shape (Shape 3) in exercise-04. <!-- needs-research: OpenCodeInterpreter is a training/inference paper, not a scoring-rubric paper; a more directly-on-topic citation for structured trajectory critique may exist. -->

## Inspect's agent harness end-to-end (Chapter 6)

- **UK AISI Inspect — main documentation site.** [inspect.aisi.org.uk](https://inspect.aisi.org.uk/). The reference site for `Task`, `Dataset`, `Solver`, `Scorer`, tools, sandbox, and `basic_agent`.
- **UK AISI Inspect — Tools.** [inspect.aisi.org.uk/tools.html](https://inspect.aisi.org.uk/tools.html). Reference for the `@tool` decorator and the docstring-derived schema Chapter 6 walks through.
- **UK AISI Inspect — Agents.** [inspect.aisi.org.uk/agents.html](https://inspect.aisi.org.uk/agents.html). Reference for `basic_agent` and Inspect's agent-loop primitives.
- **UK AISI Inspect — Sandboxing.** [inspect.aisi.org.uk/sandboxing.html](https://inspect.aisi.org.uk/sandboxing.html). Reference for the Docker / local sandbox lifecycle Chapter 6 mentions as the `sandbox="docker"` swap for SWE-bench-shaped tasks.
- **UK AISI Inspect — Eval Logs.** [inspect.aisi.org.uk/eval-logs.html](https://inspect.aisi.org.uk/eval-logs.html). Reference for the `.eval` log format that the trajectory scorer's `Score.metadata` writes into, and for the `inspect view` browser UI used in the "click through 10 trajectories" starter guidance.
- **UK AISI Inspect — Scoring.** [inspect.aisi.org.uk/scorers.html](https://inspect.aisi.org.uk/scorers.html). Reference for `@scorer`, `@metric`, and the re-scoring workflow (`inspect score` against an existing log) Chapter 6 highlights as the harness's most under-used feature.
- **UK AISI Inspect Evals repository.** [github.com/UKGovernmentBEIS/inspect_evals](https://github.com/UKGovernmentBEIS/inspect_evals). A large collection of production Inspect evals authored by UK AISI and collaborators, including SWE-bench (Verified), GAIA, and several other agent evals. Best available library of "how a real Inspect agent eval is structured."
- **UK AISI Inspect repository.** [github.com/UKGovernmentBEIS/inspect_ai](https://github.com/UKGovernmentBEIS/inspect_ai). Source of truth for the framework and its built-in tool integrations.
- **UK AI Safety Institute (2024).** "Pre-Deployment Evaluation of Anthropic's Upgraded Claude 3.5 Sonnet." [gov.uk report](https://www.gov.uk/government/publications/pre-deployment-evaluation-of-anthropics-upgraded-claude-35-sonnet). Example of a published pre-deployment eval report built on Inspect; documents the agent-eval methodology, tool inventories, and result format.
- **LangGraph — documentation.** [langchain-ai.github.io/langgraph](https://langchain-ai.github.io/langgraph/). Referenced in the "when Inspect isn't the right harness" section as an example of an in-product agent framework that is easier to instrument in place than to reimplement.
- **LlamaIndex — agents documentation.** [docs.llamaindex.ai/en/stable/module_guides/deploying/agents](https://docs.llamaindex.ai/en/stable/module_guides/deploying/agents/). Similar reference for the second in-product agent framework called out in the same section.

## Cross-cutting: reproducibility, cost accounting, and manifest discipline

- **Mitchell, M., Wu, S., Zaldivar, A., Barnes, P., Vasserman, L., Hutchinson, B., Spitzer, E., Raji, I. D., & Gebru, T. (2019).** "Model Cards for Model Reporting." *FAT\**. [arXiv:1810.03993](https://arxiv.org/abs/1810.03993). The model-card standard the SWE-bench and WebArena reproducibility manifests borrow from.
- **Gebru, T., Morgenstern, J., Vecchione, B., Vaughan, J. W., Wallach, H., Daumé III, H., & Crawford, K. (2021).** "Datasheets for Datasets." *Communications of the ACM*, 64(12), 86–92. [arXiv:1803.09010](https://arxiv.org/abs/1803.09010). The dataset-documentation standard the "pin the dataset revision" rule descends from.
- **Reuel, A., Hardy, A., Smith, C., Lamparth, M., Hardy, M., & Kochenderfer, M. J. (2024).** "BetterBench: Assessing AI Benchmarks, Uncovering Issues, and Establishing Best Practices." *NeurIPS Datasets & Benchmarks*. [arXiv:2411.12990](https://arxiv.org/abs/2411.12990). Recent survey of benchmarks against reproducibility criteria; overlaps with the Chapter 3 and exercise-02 manifest checklists.
- **NIST AI Risk Management Framework (AI RMF 1.0), 2023.** [nist.gov/itl/ai-risk-management-framework](https://www.nist.gov/itl/ai-risk-management-framework). The "Measure" function references reproducible evaluation methodology as a governance requirement; useful backstop for the "cite the harness, budget, dataset revision" rule.
